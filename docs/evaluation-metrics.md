# Метрики качества (Q1)

`metro_perception_tools/metrics.py` сопоставляет JSONL `evaluate_bag` с
разметкой `evaluation/annotations/` и считает TP/FP/FN, ложные тревоги в
минуту и ошибку дальности. `report.py` превращает результат в Markdown.

## Запуск

`scripts/evaluate_all.py` в конце прогона сам пишет `quality.json` и
`quality.md` в каталог результатов. Отдельно:

```bash
# Весь прогон: каталог с <bag>/frames.jsonl или <bag>.jsonl
ros2 run metro_perception_tools metrics /results/run-003 --root /ws \
  --output /results/run-003/quality.json
ros2 run metro_perception_tools report /results/run-003/quality.json \
  --output /results/run-003/quality.md

# Один bag
ros2 run metro_perception_tools metrics frames.jsonl \
  --annotations evaluation/annotations/doubleT_obstacle.yaml --output quality.json
```

`--root` — корень репозитория с `evaluation/`; после `colcon install` модуль
не находит его сам. Разметка, split и число объявленных кадров берутся из
`evaluation/dataset.yaml` и `evaluation/splits.yaml`, коммит — из
`manifest.json` прогона.

## Правила сопоставления

| Правило | Значение |
| --- | --- |
| Шкала времени | `bag_stamp_ns` кадра и разметки; header и wall clock не используются |
| Метка кадра | интервал разметки, содержащий кадр; на общей границе `positive` > `uncertain` > `negative`; вне интервалов — `unlabeled`, не оценивается |
| TP / FN (кадры) | на `positive`: `OBSTACLE` — TP, любое другое состояние — FN. **`UNKNOWN` на positive — пропуск**, отдельно показан как `unknown_on_positive` |
| FP (кадры) | `OBSTACLE` на `negative`; прочие состояния — `tn_or_unknown` |
| `uncertain` | показывается, но не входит в TP/FP/FN |
| Событие тревоги | кадры `OBSTACLE` с разрывом ≤ 0,5 с (`--event-gap-s`) — одно событие |
| FP-событий/мин | события тревоги на negative / длительность negative-кадров |
| Уровень состояния | кадровые TP/recall/precision и «событие обнаружено» (хотя бы один `OBSTACLE` внутри события) считаются по состоянию кадра, тревога не сопоставляется с объектом. Это **верхние оценки** (`basis: state_level_upper_bound`); FN — нижняя оценка |
| Уровень объекта | на reference-кадрах с `person_roi_assumed_m`: кадр ближе 50 мс (`--stamp-tolerance-s`); `hit` — `OBSTACLE` и центр кандидата в области ± 0,5 м (`--roi-margin-m`); `wrong_object` — `OBSTACLE` без такого кандидата; `miss` — другое состояние. `object_confirmed` и дальность первого сопоставленного кандидата — по hit |
| Ошибка дальности | только для `hit` с измеренной эталонной дальностью |
| Покрытие | геометрическое: `evaluated_range_m > 0`; медиана дальности берётся по всем размеченным кадрам с ненулевой дальностью, причины `UNKNOWN` перечисляются отдельно. В JSON также есть `decision_coverage` (`state != UNKNOWN`), но при калибровке ASSUMED на отрицательных записях это в основном доля ложных тревог, а не подтверждение свободного пути; поэтому в таблице по bag его нет. `evaluation_region_valid` не используется: при сравнении с историей детектор намеренно держит его `false` |
| Длительность тревоги | сумма оценённых интервалов тревожных кадров с шагом по медианной частоте записи; одиночная тревога получает один шаг, только если частоту можно оценить по соседним кадрам. При одном кадре с тревогой результат N/A. `event_span_s` отдельно показывает сумму расстояний между первой и последней тревогой каждого события |
| Происхождение | `run_reproducible` проверяет manifest прогона детектора: чистый коммит, образ, входные bag, профили, полноту выгрузки и, для нового формата, SHA-256 выходного JSONL. `scoring_current` отдельно сравнивает сохранённые в manifest hashes splits, annotations и файлов scorer с текущими, а также метку `scoring_executed_from: source_tree`, которую `evaluate_all.py` пишет, когда запускает scorer из этих исходников (это метка, не отдельная проверка). В `skipped` запись вне `selected_bags` помечается `not selected`, выбранная без результата — `no results`. Старые manifest без scoring hashes сохраняют воспроизводимость прогона при выполнении остальных условий, но версию scorer исходного прогона подтвердить нельзя; пересчёт JSONL текущим кодом возможен отдельно |
| Пустая выборка | `None` / N/A, не 0 и не 100%; precision — N/A без positive-кадров |
| Итоги по split | суммы счётчиков, доли пересчитываются из сумм, а не усредняются |

Прогревочные кадры (`BASELINE_WARMUP`) дают `UNKNOWN` и поэтому не создают FP;
отдельного исключения для них нет.

## Базовый результат G2

Прогоны `scripts/evaluate_all.py` в образе `metro-lidar:q1` (`docker/Dockerfile`,
стадия `universal`, Release) с чистого checkout коммита Q1 (SHA записан в
`manifest.json`): `results/q1-research` (шесть bag, `--full-scan-research`) и
`results/q1-official` (`doubleT_obstacle` штатным профилем). В обоих
`quality.json` `run_reproducible: true` и `scoring_current: true` без замечаний:
manifest фиксирует коммит, образ, входные bag, профили, хеши разметки, splits,
scorer и выходных JSONL. Решения детектора кадр в кадр совпали с прежним
прогоном G2 (`results/g1-work/g2fix2`). Калибровка ASSUMED.

```bash
python3 scripts/evaluate_all.py --dataset-root /data --output-dir /results/q1-research \
  --full-scan-research --bags doubleT_obstacle doubleT_platform roundT_doubleT \
  roundT_pressureGate_roundT roundT_squareT_pressureGate_squareT squareT_platform_squareT_switch
```

0/35 объектных попаданий, 0 ложных тревог. Это честный результат без допущения
об оси; пять секторных bag в штатном и исследовательском режимах одинаковы.

FP-колонки рассчитаны только по отрицательным кадрам; геометрия и медиана
дальности — по всем размеченным кадрам соответствующего bag.

Событие `person_enters_track_01`: по состоянию 14/35 кадров с тревогой.
На всех 35 кадрах область человека выделена по движущейся группе сырых точек
в просмотренной панораме, независимо от кандидатов детектора. По объекту:
11 попаданий, 21 пропуск (`UNKNOWN`) и 3 тревоги на других объектах.
Первое совпадение с человеком — через 0,39 с, кандидат на 6,65 м. Эталонная
дальность измерена только для двух поздних кадров: ошибки +0,13 и +0,10 м
при погрешности эталона 0,2 м. p95 здесь — время одной обработки в
Release-сборке, не замер Q2.

Три тревоги на другом объекте приходятся на кадры +19,29…+19,49 с:
кандидаты в них лежат вне области человека. Области размечены по
последовательности из 35 сырых облаков; локальная контактная панорама
сохранена в `results/q1-positive-points/montage.png`. В ранних областях
контрольный пустой кадр содержит 8–50 фоновых точек против более 1800
точек на кадрах с человеком. Рамки шириной 0,7 м по X следуют ручной
траектории, а не подгоняются по всем точкам каждого кадра; на +17,59 и
+17,68 с они охватывают около 58% и 77% отличающихся точек человека.

Для сравнения старый скользящий эталон без компенсации движения
(`results/b0-analysis/doubleT_platform-rolling.jsonl`) даёт на
`doubleT_platform` 276/345 FP-кадров и 6 событий (10,46/мин).

**Ограничения.**

- Область человека размечена на всех 35 положительных кадрах. Объектная
  покадровая доля — 11/35 (31,4%) на единственной положительной записи;
  кадровые 40% и precision по состоянию остаются верхними оценками.
  Области и ориентация лидара предполагаемые, а эталонная дальность есть
  только для двух кадров.
- Один положительный bag, и он в development: recall на validation не определён.
- FP-событий/мин занижает длинные серии: 95 кадров `roundT_doubleT` — всего
  2 события, поэтому смотреть надо и на FP-кадры, и на оценку занятости
  тревогой `alarm_duration_s` (9,32 с для этого bag).
- Результат с человеком получен только с исследовательским допущением об оси
  полного скана.
