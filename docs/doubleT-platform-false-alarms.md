# Разбор 276 тревожных кадров `doubleT_platform`

Дата: 23.09.2026. Источник числа 276 —
`results/b0-analysis/doubleT_platform-rolling.jsonl`, 345 кадров, режим
`geometric_rolling`. Это **кадры** состояния `OBSTACLE`, а не 276 независимых

выборочный просмотр depth-панорам
(`evaluation/annotations/doubleT_platform.yaml`). Без независимой проверки
габарита и калибровки оценка остаётся предварительной.

У 263 из 276 тревожных кадров **ближайший** кандидат имеет
`|center.y| ≥ 1,5 м` при предполагаемой полуширине коридора 2 м.
Всего у 276 кадров 2569 кандидатов, 2145 из них находятся в этой краевой
полосе. Эти координаты измерены в предполагаемой системе `lidar_assumed`.
Медиана числа кандидатов на тревожный кадр — 9, медиана сообщённой ближней
дальности — 9,29 м. Панорамы показывают стены, боковые конструкции и смену
геометрии двойного тоннеля. По одним bbox нельзя надёжно назвать физический
объект каждого из 2569 кластеров.

**Причина, поддержанная сравнением прогонов:** прежний скользящий эталон
сопоставлял дальности без компенсации движения поезда. Боковые структуры и
повторяющиеся элементы тоннеля меняют видимое положение и проходят как новый
передний план. Это объясняет длинную серию тревог и концентрацию кандидатов у
края коридора; точное соответствие каждого кандидата поверхности остаётся
гипотезой. Простое сужение коридора без подтверждённого габарита могло бы
скрыть реальное препятствие.

Контрольный прогон G2 из `results/g1-work/g2fix2/doubleT_platform.jsonl`
с компенсацией движения содержит 9/345 тревожных кадров. При сопоставлении по
`frame_sequence` из старых 276 исчезли 270, сохранились 6, появились 3 других.
Остаток — кадры 235, 263–266, 325–326, 328–329. На 263–266 скорость
снижается с 0,54 до 0,07 м/с; на 325–329 она близка к нулю. Это указывает на
отдельный случай торможения/остановки и недостаточного подтверждения фона.
Все девять имеют `ego_motion_valid: true`; по этому флагу их нельзя отнести к
потере одометрии. Устранение старых тревог не доказывает полноту обнаружения
человека: положительный bag уже участвовал в разработке и использует
предполагаемую ориентацию полного скана.

## Воспроизведение

В обоих JSONL сопоставлять `frame_sequence`, время брать из `bag_stamp_ns`.
Первый timestamp: `1788359712599450851`. Кандидатные координаты — из
`candidates[].center`; порог краевой полосы `1.5` м. События выше объединены,
если разница `bag_stamp_ns` двух последовательных тревожных кадров не более
`500000000` нс; более длинный разрыв начинает новое событие. Изменение этого
правила меняет число событий, но не 276 тревожных кадров. Для оценки FP/min
требуется согласованный интервал отрицательной разметки и честное указание,
что он основан на описании владельца и выборочном просмотре.
